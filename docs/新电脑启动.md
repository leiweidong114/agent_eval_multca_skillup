先说明一个关键现状：目前已经发布的 windows-runtime-20260910 Release 里包含的是旧版 JustDo 安装包。评测平台代码可以从 dev 分支拉取最新版，但要完整验证最新的 JustDo 主/子 Agent 追踪功能，需要先重新制作并上传包含新版 JustDo 的 Runtime Release；或者在新电脑上单独安装新版 JustDo。
下面是新 Runtime Release 发布后的完整部署流程。
一、新电脑准备
系统建议：
- Windows 10/11 x64
- 至少 20 GB 可用空间
- 已安装 Git
- PowerShell 5.1 或 PowerShell 7
- 首次下载 Release 和仓库时需要联网
- Release 下载完成后，安装、编译、运行可以离线
验证 Git：
git --version
如果命令不存在，先安装 Git for Windows。
二、下载两个内容
需要下载：
1. Git 仓库 dev 分支：提供评测后端、前端和自定义 Multica Runner 代码。
2. Runtime Release ZIP：提供 Go、Node.js、Python、wheelhouse、npm cache、Skill-Up/Multica 源码与 vendor、JustDo 安装包、公开题库。
建议目录：
D:\agent-eval\
├── agent_eval_multca_skillup\     # Git 仓库
└── release\                       # Release ZIP 解压结果
创建目录：
New-Item -ItemType Directory -Force D:\agent-eval
New-Item -ItemType Directory -Force D:\agent-eval\release
从 GitHub Release 页面下载：
agent-eval-runtime-windows-x64-portable.zip
假设下载到了：
D:\Downloads\agent-eval-runtime-windows-x64-portable.zip
解压：
tar.exe -xf D:\Downloads\agent-eval-runtime-windows-x64-portable.zip `
  -C D:\agent-eval\release
解压后应当能看到：
D:\agent-eval\release\
├── toolchains\
├── python\wheelhouse\
├── frontend\npm-cache\
├── sources\skill-up\
├── sources\multica\
├── justdo\
└── question-bank\
新版设计中不需要 prebuilt\ 目录。
三、拉取最新版代码
git clone --branch dev --single-branch `
  https://github.com/leiweidong114/agent_eval_multca_skillup.git `
  D:\agent-eval\agent_eval_multca_skillup
进入仓库：
Set-Location D:\agent-eval\agent_eval_multca_skillup
确认分支：
git branch --show-current
git log -1 --oneline
第一条应输出：
dev
四、运行离线安装
允许当前 PowerShell 进程执行脚本：
Set-ExecutionPolicy -Scope Process Bypass -Force
默认安装：
.\install_windows.ps1 `
  -ReleaseRoot D:\agent-eval\release
安装脚本会自动完成：
- 安装/解压 Go 1.26.7
- 安装/解压 Node.js 26.1.0
- 安装 portable CPython 3.12.14
- 从本地 wheelhouse 创建 Python 虚拟环境
- 从本地 npm cache 安装前端依赖
- 复制 Skill-Up 和 Multica 源码、vendor
- 使用 -mod=vendor 离线编译 Skill-Up
- 离线编译 Multica Runner
- 安装 JustDo
- 复制公开题库
- 创建 .env
- 执行环境诊断
如果希望看到 JustDo 的图形化安装界面：
.\install_windows.ps1 `
  -ReleaseRoot D:\agent-eval\release `
  -InteractiveJustDo
如果系统缺少 VC++ Runtime，可以同时安装：
.\install_windows.ps1 `
  -ReleaseRoot D:\agent-eval\release `
  -InstallVCRuntime
如果新电脑已经单独安装了最新版 JustDo：
.\install_windows.ps1 `
  -ReleaseRoot D:\agent-eval\release `
  -SkipJustDo
五、检查安装产物
安装完成后检查：
Test-Path .\backend\.runtime\windows\go\bin\go.exe
Test-Path .\backend\.runtime\windows\node\node.exe
Test-Path .\backend\.runtime\windows\python\Scripts\python.exe
Test-Path .\backend\.tools\windows\skill-up.exe
Test-Path .\backend\.runtime\windows\bin\multica-eval-runtime.exe
正常情况下都应返回：
True
六、配置 .env
安装脚本会根据 .env.example 创建：
D:\agent-eval\agent_eval_multca_skillup\.env
编辑它：
notepad .env
至少配置以下内容。
1. LiteLLM 地址和密钥
LITELLM_PROFILE=litellm
LITELLM_API_BASE=http://你的LiteLLM服务器:4000/v1
LITELLM_API_KEY=评测调用使用的密钥
LITELLM_MASTER_KEY=能够创建和删除虚拟Key的MasterKey

LITELLM_MODEL=你的默认模型
LITELLM_JUDGE_MODEL=你的评判模型
AGENT_TEST_MODEL=你的测试模型
注意：
- LITELLM_API_BASE 一般需要带 /v1。
- LITELLM_MASTER_KEY 必须有 /key/generate 和 /key/delete 权限。
- 正式评测时，平台会为每次评测生成唯一虚拟 Key 和 key_alias，用于归集本次评测产生的交互。
2. 内网模型请求头
LITELLM_USER_AGENT=OpenAI/Python
LITELLM_X_COOKIE=11
用户工号不需要固定写到 .env。登录后，平台会把工号动态放入：
x-user-account: 用户登录时输入的工号
只有标记为内网网关的模型配置才应该注入这些请求头，避免影响外网模型。
检查 backend/config/models.yaml 中相应模型配置是否包含：
internal_gateway: true
3. 登录会话密钥
生成随机密钥：
$secretBytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($secretBytes)
[Convert]::ToBase64String($secretBytes)
把输出结果写入：
AGENT_EVAL_SESSION_SECRET=刚才生成的随机字符串
AGENT_EVAL_SECURE_COOKIE=false
如果以后通过 HTTPS 访问，将其改为：
AGENT_EVAL_SECURE_COOKIE=true
登录是“假登录”：
- 工号会保存到签名会话 Cookie
- 密码不校验
- 密码不会保存
- 工号用于模型调用归因和内网请求头
4. LiteLLM 数据库
可以用完整连接串：
DATABASE_URL=postgresql://litellm:你的密码@数据库地址:5432/litellm
DATABASE_ENABLED=true
也可以分别设置：
DATABASE_ENABLED=true
DATABASE_HOST=127.0.0.1
DATABASE_PORT=5432
DATABASE_NAME=litellm
DATABASE_USER=litellm
DATABASE_PASSWORD=你的密码
DATABASE_SSLMODE=prefer
若要让评测结果包含请求和响应正文：
DATABASE_TRACE_ENABLED=true
DATABASE_TRACE_INCLUDE_CONTENT=true
DATABASE_TRACE_LIMIT=500
DATABASE_RETENTION_DAYS=30
DATABASE_MAX_CONTENT_CHARS=20000
DATABASE_TRACE_LIMIT=500 是单次分页/查询保护值，不代表数据库最多只能保存或总共只能获取500条。数据量更大时应通过分页继续抓取。
同时必须保证 LiteLLM Proxy 本身开启了数据库日志写入；评测平台只能读取 LiteLLM 实际写进数据库的字段。
七、检查 JustDo 路径
默认配置类似：
JUSTDO_AGENT_EXECUTABLE=D:/tools/JustDo/JustDo-agent.exe
AGENT_PATHS_JSON={"justdo":"D:/tools/JustDo/JustDo-agent.exe"}
确认文件存在：
Test-Path 'D:\tools\JustDo\JustDo-agent.exe'
如果安装到了其他位置，修改 .env 中这两个路径。
必须使用包含以下提交或更新版本的 JustDo：
873646ea feat(eval): 完善评测会话归因与工具遥测
否则评测平台虽然能运行，但不能保证获得最新的 JustDo 主 Agent、Subagent 和工具调用遥测。
八、执行环境诊断
基础诊断：
.\doctor.ps1
严格检查所有必要配置：
.\doctor.ps1 -RequireConfiguration
有错误时先不要启动评测，按照输出补齐 .env、JustDo 路径或数据库配置。
九、启动服务
.\start.ps1 -OpenBrowser
start.ps1 是方便入口，内部调用完整的 start-all.ps1。
两者区别：
- start.ps1：日常使用的简短入口。
- start-all.ps1：真正负责加载 .env、选择端口、启动前后端、执行健康检查、记录 PID 和日志。
启动脚本如果发现 8000 或前端默认端口被占用，会自动选择其他可用端口。以脚本最终打印的地址为准。
查看服务状态文件：
Get-Content .\backend\.runtime\service-manager\services.json
查看后端健康状态；如果后端端口是 8000：
Invoke-RestMethod http://127.0.0.1:8000/api/health
十、登录并进行首次验证
浏览器打开平台后：
1. 输入工号。
2. 密码随意输入。
3. 登录。
4. 进入模型测试页面。
5. 选择一个可用模型执行最小测试。
6. 再创建一次原理图生成评测。
7. Agent 选择 JustDo。
8. 运行完整评测。
需要重点确认：
- 登录页面正常出现。
- 当前用户显示正确工号。
- 内网模型能够调通。
- 外网模型仍可调用。
- 每个评测任务生成独立虚拟 Key 和唯一 key_alias。
- 数据库交互记录能够按工号、任务、模型、Agent 归集。
- JustDo 主 Agent 和 Subagent 可区分。
- 工具调用能够被获取。
- 任务结束后虚拟 Key 按配置清理，但数据库历史交互仍然保留。
如果没有出现登录页面，先清理旧页面缓存和 Cookie，或者使用隐私窗口重新打开脚本打印的最新地址。
十一、查看日志
后端错误：
Get-Content `
  .\backend\.runtime\service-manager\backend.stderr.log `
  -Tail 200
前端错误：
Get-Content `
  .\backend\.runtime\service-manager\frontend.stderr.log `
  -Tail 200
后端正常输出：
Get-Content `
  .\backend\.runtime\service-manager\backend.stdout.log `
  -Tail 200
十二、停止和重启
停止：
.\stop.ps1
重启：
.\restart.ps1 -OpenBrowser
如果只修改了 .env，直接运行 restart.ps1 即可。
十三、新电脑修改代码后重新编译
重新构建前端：
.\rebuild.ps1 -Target Frontend -Restart
重新编译 Skill-Up：
.\rebuild.ps1 -Target SkillUp -Restart
重新编译 Multica：
.\rebuild.ps1 -Target Multica -Restart
全部重新编译：
.\rebuild.ps1 -Target All -Restart
普通重新编译不需要联网，依赖来自 Runtime Release。
不建议在 Windows 上对 Skill-Up 随意增加 -Test，因为其部分上游测试依赖 Bash/Linux 环境；这不影响 Windows 可执行文件的正常编译和使用。
十四、以后更新 dev 代码
如果没有未提交的本地修改：
Set-Location D:\agent-eval\agent_eval_multca_skillup
git checkout dev
git pull --ff-only origin dev
.\rebuild.ps1 -Target All -Restart
如果修改过本地源码，先提交或保存修改，避免 git pull 覆盖或产生冲突。
总结来说，新电脑的标准流程是：
下载 Runtime Release
→ 解压
→ 拉取 dev 分支
→ 运行 install_windows.ps1
→ 配置 .env
→ doctor.ps1 检查
→ start.ps1 启动
→ 登录
→ 测试模型
→ 运行原理图完整评测
→ 检查主/子 Agent 与工具调用数据
